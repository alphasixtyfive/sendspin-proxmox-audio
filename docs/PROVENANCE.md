# Upstream sources and configuration baseline

`upstream-pins.json` is the machine-readable record. The deployment downloads **unchanged official Sendspin CLI 0.4.0** from its own release, built at `45ff8b00e72ad1572a39e6e8ce21891748ab7d9e`, linked to released core 0.9.5 `b95cf854a784ed308b1f8fe9697f414b02768ddd`. No renderer source or release binary is vendored into this repository.

The verified amd64 archive SHA256 is `40efcab39ef303d026d8880ad1ada7b53b29e806114ae3744f9ed33daee0c5d9`; binary SHA256 is `350b891ed3f11b73cf428cb7dc8bc8a9dd809892515c69fb2bca6724867cda7b`. The official release's `SHA256SUMS` SHA256 was `5376bcf312e2143d02e58ccfad0310371010b46dc8b9211c1fe01d7abacf455b`. Inspect the archive's BUILD-INFO and `--version`; the binary links optional output libraries, but configuration selects native PipeWire. [Release](https://github.com/Sendspin/sendspin-cpp-cli/releases/tag/v0.4.0), [source](https://github.com/Sendspin/sendspin-cpp-cli/tree/45ff8b00e72ad1572a39e6e8ce21891748ab7d9e), [license](https://github.com/Sendspin/sendspin-cpp-cli/blob/45ff8b00e72ad1572a39e6e8ce21891748ab7d9e/LICENSE).

Distribution baseline: Debian 13 amd64, PipeWire 1.4.2 and WirePlumber 0.5.8 configuration APIs. Normal Debian security updates are expected; these are reviewed baselines, not apt holds. Native sound driver/kernel comes from the Proxmox host.

The user-unit template adapts the upstream service model to multiple instances sharing a normal lingering PipeWire user session. Unique config, port, state and control socket are deployment configuration. Upstream lifecycle/retry semantics remain unchanged. [Upstream service/configuration](https://github.com/Sendspin/sendspin-cpp-cli/tree/45ff8b00e72ad1572a39e6e8ce21891748ab7d9e/packaging).

The physical outputs use the stock ALSA adapter pattern in [PipeWire1.4.2's configuration](https://github.com/PipeWire/pipewire/blob/1.4.2/src/daemon/pipewire.conf.in#L292). Named ALSA paths need distinct explicit clock names: [ALSA initialization](https://github.com/PipeWire/pipewire/blob/1.4.2/spa/plugins/alsa/alsa-pcm.c#L1008) cannot infer a numeric card index from a name, and clock-name equality controls rate matching. Resampling remains available. The normal [WirePlumber suspend policy](https://github.com/PipeWire/wireplumber/blob/0.5.8/src/scripts/node/suspend-node.lua) handles Audio/Sink nodes without a parent Device. Static objects have no discovery retry; `nofail` skips failed creation in [configuration loading](https://github.com/PipeWire/pipewire/blob/1.4.2/src/pipewire/conf.c#L808).

This avoids a measured platform interaction. The [Proxmox autodev hook](https://github.com/proxmox/pve-container/blob/master/src/lxc-pve-autodev-hook#L20) creates regular-file mount placeholders; a bound sound device can report a regular directory entry while stat resolves its character type. The [PipeWire1.4.2 enumerator](https://github.com/PipeWire/pipewire/blob/1.4.2/spa/plugins/alsa/alsa-udev.c#L264) counts only character directory entries. Direct adapters bypass that gate; both packages remain unchanged. The CT needs no host udev database mount.

The stereo routing templates use stock loopback channels/targets and client stream rules. Client fail-closed rules match only this example's exact application/output targets. They apply after media.class is determined. WirePlumber target policy combines dont-move/dont-fallback with lingering loopback outputs to wait for the same hardware target. These are supported properties, not patched source. [PipeWire1.4.2 loopback](https://github.com/PipeWire/pipewire/blob/1.4.2/src/modules/module-loopback.c), [stream rules](https://github.com/PipeWire/pipewire/blob/1.4.2/src/pipewire/stream.c), [WirePlumber0.5.8 target selection](https://github.com/PipeWire/wireplumber/blob/0.5.8/src/scripts/linking/find-defined-target.lua).

Additional references: [ALSA USB channel mapping](https://github.com/alsa-project/alsa-lib/blob/v1.2.14/src/conf/cards/USB-Audio.conf), [Proxmox container architecture](https://github.com/proxmox/pve-docs/blob/master/pct.adoc), [MA Sendspin support](https://www.music-assistant.io/player-support/sendspin/).

The optional host recovery component is deployment code in this repository, not an upstream audio patch. It uses supported `pct` lifecycle operations and stock PipeWire tools. Physical adapter arguments are read from the merged configuration through `pw-config` and `spa-json-dump`, then recreated through `pw-cli`; [the PipeWire1.4.2 utility source](https://github.com/PipeWire/pipewire/blob/1.4.2/spa/tools/spa-json-dump.c) explains the no-filename stdin conversion. Host ALSA's existing saved state remains the sole calibration source. Because the operation runs as host root, its private mapping and owned units/executable require administrator review; no host/HA/MA credential is embedded in it. See [installation, maintenance boundaries and removal](USB-RECOVERY.md).
