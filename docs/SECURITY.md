# Container and hardware boundaries

Use a dedicated **unprivileged Debian 13 amd64 LXC** with normal Proxmox isolation. This repository does not provide a privileged container, custom kernel, broad device passthrough or host audio service. It does not require nesting, Docker, unconfined AppArmor, writable host sysfs, raw USB bus access or extra Linux capabilities.

The Proxmox host's normal `snd_usb_audio` driver owns the soundcards. A CT shares that kernel; installing a CT driver cannot replace it. Remove conflicting VM USB passthrough only after arranging a reversible handoff. Preserve unrelated USB devices and services. Do not assign the same hardware to two audio servers.

The optional [USB recovery component](USB-RECOVERY.md) runs on the host as root to validate hardware, restore existing calibration and coordinate narrow device grants. Review its source and private hardware map before separate installation. The map and runtime must be root-owned and not writable by other users. The udev worker only queues an event; the systemd operation owns bounded work. It does not expose a network API, handle HA/MA credentials, grant capture/raw-USB access or run a host audio server.

Grant only each selected card's playback PCM and control device using supported Proxmox `devN` entries. Observe the actual host paths, major/minor and CT-local audio GID. Example path shapes are `/dev/snd/controlC<N>` and `/dev/snd/pcmC<N>D0p`; `<N>` is not stable hardware identity. Use owner 0, the CT-local audio GID and mode 0660. Do not pass all `/dev/snd`, capture devices, sequencer, `/dev/bus/usb` or the host's complete audio group mapping. [Proxmox device schema](https://github.com/proxmox/pve-container/blob/master/src/PVE/LXC/Config.pm).

One unprivileged `sendspin-cli` account owns the packaged PipeWire/WirePlumber user manager and all player processes. Give it only the required playback/control access. Linger makes ordinary user services independent of a desktop login. Do not run PipeWire as root or add realtime capabilities merely to suppress a warning.

Before the first control-device grant, mask CT `alsa-restore.service` and `alsa-state.service`, and suppress its `90-alsa-restore.rules` through a standard same-name `/etc/udev/rules.d` symlink to `/dev/null`. Host ALSA owns fixed calibration; a CT must not overwrite/restore a second saved state onto the same hardware. The service masks alone do not suppress udev RUN commands. Verify both layers remain disabled after boot. Reload udev only if already active; no extra daemon is required.

Use explicit stock PipeWire ALSA adapters with persistent host card IDs, and disable WirePlumber's automatic ALSA monitor. Proxmox `devN` can bind a character device onto a regular-file placeholder: stat sees the real device, while directory enumeration reports a regular entry. PipeWire1.4.2's automatic ALSA enumerator counts only character directory entries. This combination was measured during the pilot; explicit adapters avoid that discovery gate without changing either package or broadening access. See [provenance](PROVENANCE.md).

No host udev database, host control socket, metadata-copy job or CT udev daemon is required. Stable port-to-card-ID assignment and fixed mixer calibration remain host responsibilities. Proxmox `devN` grants specific nodes; a card returning with a different minor may require updating the supported mapping and restarting the CT. Explicit adapters are created at PipeWire startup; test absent-at-start and USB return, and retain the documented manual restart boundary. No device watcher or hotplug daemon is added.

Inspect the **installed host** ALSA restore rule, not only upstream source. Debian [bug1104719](https://bugs.debian.org/cgi-bin/bugreport.cgi?bug=1104719) affected alsa-utils1.2.14-1: missing rule labels could select a cached HDA card instead of the newly added USB card. The official correction is1.2.14-2. A fixed compatible distribution package and a bounded selected-card restore proof are required before relying on calibration persistence; this repository does not patch vendor rules or enable sid. Verify unrelated live controls as well as saved state.

Sendspin 0.4 uses encrypted transport and pairing. Private state contains identity keys and pairing secrets; tokens also authorize pairing. Keep per-zone state private and backups access-controlled. Never commit state, tokens or private topology. Restrict network exposure to the trusted LAN/server connection. The sample configs require pairing and contain no credentials.
